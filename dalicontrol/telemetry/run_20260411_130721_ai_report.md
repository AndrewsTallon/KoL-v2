# Test Report: AI-Based Adaptive Lighting Control

## Abstract

This short report summarizes one test run of the KoL-v2 adaptive desk-lighting system for use in an AI master thesis draft. The dataset was generated by the application during an AI-control session using participant profile `participant-01`. The run demonstrates closed-loop lighting adaptation based on occupancy, ambient illuminance, circadian phase, weather context, and learned user preference signals. The results indicate that the controller produced explainable lighting decisions, adapted brightness and color temperature over the afternoon-to-evening period, and switched the lamp off during extended vacancy periods.

## System Under Test

KoL-v2 is an AI-powered smart lighting control system using ESP32-based sensing, DALI lighting control, telemetry logging, and a Python control engine. The application records sensor and controller state into CSV telemetry files. For this test, the controller operated in `ai` mode and produced both machine actions and natural-language rationales for selected decisions.

The tested input file was:

`dalicontrol/telemetry/run_20260411_130721_ai.csv`

## Experimental Setup

The session was recorded on 2026-04-11 from `13:07:23` to `21:12:45`, covering approximately 8 hours and 5 minutes of wall-clock time. The telemetry file contains 5,860 rows. The internal `runtime_s` field reached 10,166.6 seconds, or approximately 2 hours and 49 minutes, so the wall-clock duration and application runtime should be interpreted separately.

The logged variables included:

- Occupancy: raw and filtered presence states.
- Ambient light: raw lux and smoothed lux values.
- Lamp state: off state, DALI level, and correlated color temperature.
- AI decision metadata: action, reason, rationale, circadian phase, weather context, target lux, and brightness adjustment terms.

## Method

The report was produced by parsing the CSV telemetry and summarizing controller state, action frequency, occupancy proportion, lamp state, and environmental adaptation. Actions were treated as explicit controller interventions when the `action` column was non-empty. Occupancy was evaluated using `filt_occupied`, because it represents the processed state used for control rather than raw sensor presence.

The analysis is descriptive rather than inferential. No statistical hypothesis test was applied, since this single run is intended as an application-generated test artifact rather than a full participant study.

## Results

The controller logged 58 explicit action rows. The most common action reason was `adaptive_eval` with 33 occurrences, followed by `adaptive_vacant_dim` with 9 occurrences, `presence_restore` with 7 occurrences, `adaptive_vacant_off` with 7 occurrences, and `adaptive_dim_restore` with 2 occurrences.

Filtered occupancy was present in 33.8% of samples, while raw presence was detected in 33.2% of samples. The lamp was logged as off in 64.6% of samples. This suggests that vacancy handling was active during the run and that the lamp spent a substantial portion of the session in an energy-saving state.

The smoothed ambient illuminance averaged 144.4 lux, with a minimum of 0 lux and a maximum of 474.1 lux. The logged DALI lamp level averaged 57.5, with values ranging from 25 to 226. Because this is a DALI level rather than a direct power measurement, it should be treated as a control-output proxy rather than a direct energy-consumption value.

The controller adapted decisions across the following circadian phases:

| Circadian phase | AI action count | Average target lux |
| --- | ---: | ---: |
| Midday peak alertness | 11 | 488.9 |
| Afternoon transition | 25 | 368.9 |
| Evening wind-down | 3 | 266.4 |
| Night wind-down | 1 | 176.3 |

The logged color-temperature values show a clear temporal adaptation pattern. The most frequent CCT values included approximately 6494 K, 3937 K, 2801 K, and 5682 K. This supports the intended behavior: cooler light during focus-oriented periods and warmer light during evening or wind-down periods.

## Example Controller Behavior

At the beginning of the session, the controller selected a cool white setting of approximately 6500 K and a low brightness percentage because the ambient light was already bright. The rationale explicitly referenced the circadian phase, weather context, ambient lux, target lux, learned preference adjustment, and weather adjustment.

Later, when the desk was vacant, the system dimmed the lamp to 10% as a warning state and then issued an `off()` action after continued vacancy. When presence returned, the controller restored brightness using `presence_restore`. This demonstrates a practical closed-loop behavior: maintain comfort when occupied, reduce output when vacant, and restore lighting after re-occupation.

## Discussion

The run shows three qualities relevant to an AI master thesis:

1. Context-aware adaptation: the controller adjusted target lux and CCT according to circadian phase and ambient light.
2. Explainability: action rows contained human-readable rationales, making the AI behavior auditable.
3. Energy-aware control: vacancy dimming and shutoff were triggered repeatedly, with the lamp logged as off for most samples.

The results are promising for a test run because the system did not only produce control commands; it also recorded the reasons behind those commands. This is important for evaluating AI-assisted building or workplace automation, where user trust and interpretability are often as important as raw control performance.

## Limitations

This report is based on a single telemetry run for one participant profile. It does not compare AI mode against a baseline controller, and it does not include direct energy measurements. The off-state percentage and DALI level should therefore be interpreted as behavioral indicators, not final energy-saving metrics.

The wall-clock timestamp range and `runtime_s` field differ substantially. This may be expected if `runtime_s` represents active application runtime rather than elapsed log time, but it should be clarified before using the dataset in final thesis analysis.

## Conclusion

This application-generated test run supports the feasibility of an explainable AI lighting controller for desk environments. The KoL-v2 system adapted brightness and CCT across circadian phases, responded to occupancy changes, and logged rationales for AI actions. For a full thesis evaluation, the next step would be to compare multiple AI-mode runs against baseline runs using comfort, illuminance stability, user intervention frequency, and measured energy consumption as evaluation metrics.
